What EventBridge is useful for

EventBridge is useful to detect that the certificate has changed and trigger a workflow:

Certificate V1 → V2
       │
       ▼
EventBridge detects update
       │
       ▼
Trigger Refresh Controller

But EventBridge does not control Lambda warm containers.

Your example

Initially:

Lambda A

Container 1 → V1 (idle)
Container 2 → V1 (idle)
Container 3 → V1 (busy)

Certificate changes:

V1 → V2

EventBridge triggers the Refresh Controller.

What EventBridge does
EventBridge
    ↓
Trigger your Lambda/function/workflow
What EventBridge does NOT do
❌ Destroy Container 1
❌ Destroy Container 2
❌ Destroy Container 3
❌ Clear their Java cache
❌ Force the next request into a new container
After refresh, a new API request arrives
Case 1: Idle warm container exists
New Request
     ↓
Container 1 (already warm)
     ↓
Uses cached V1 ❌

AWS may reuse the idle warm container.

Case 2: All existing containers are busy
New Request
     ↓
All warm containers busy
     ↓
AWS creates Container 4
     ↓
Container initialization
     ↓
Reads Certificate V2 ✅
So what is the real use of EventBridge here?

EventBridge is the notification/trigger mechanism:

Certificate Updated
       ↓
EventBridge
       ↓
Start your update workflow

It is not a Lambda container refresh mechanism.

Your two issues are correct
Issue	What happens
Old warm containers	Continue to exist and may have V1
New request	Can reuse an idle warm container with V1
New container	Reads V2 during initialization
EventBridge	Detects/triggers update but cannot clear warm-container memory
Final conclusion

EventBridge tells your application that the certificate changed. It does not force AWS Lambda to destroy or refresh all warm containers.
