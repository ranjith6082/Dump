The main issue with this approach is that you cannot directly refresh or replace all existing warm containers of Lambda A and Lambda B.

Simple example

Initially:

Lambda A → 10 warm containers → all have old certificate V1
Lambda B → 10 warm containers → all have old certificate V1

Certificate is updated:

V1 → V2

EventBridge triggers:

Refresh Controller → Lambda A and Lambda B

You expect:

All old warm containers → replaced with new containers containing V2

What actually happens

Suppose after refresh, a new API request comes to Lambda A.

AWS may send that request to one of the existing 10 warm containers.

That warm container still has:

Certificate V1 ❌

It does not automatically guarantee that AWS creates a new container.

A new execution environment with V2 is created only when Lambda needs additional capacity (for example, existing containers are busy).

Main issue

Your refresh Lambda cannot force AWS Lambda to replace every existing warm container.

So after certificate rotation:

Old warm container → may still serve requests with V1
New container → reads and uses V2
