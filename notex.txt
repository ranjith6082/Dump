No. Executing EventBridge or invoking a “Refresh Lambda” does not automatically destroy existing warm containers.

Example

Initially, one Lambda has:

Lambda
├── Warm Container 1 → Certificate V1
├── Warm Container 2 → Certificate V1
└── Warm Container 3 → Certificate V1

Certificate is updated:

V1 → V2

Then:

EventBridge
    ↓
Refresh Lambda
    ↓
Invoke/refresh Lambda
What happens next?

The three old warm containers are not automatically destroyed.

Lambda
├── Warm Container 1 → V1 (still may exist)
├── Warm Container 2 → V1 (still may exist)
└── Warm Container 3 → V1 (still may exist)

When a new API request comes:

New API Request
       ↓
Lambda
       ↓
AWS chooses an available execution environment
       ↓
May use Container 1 → V1 ❌

Or, if additional capacity is required:

New API Request
       ↓
All existing containers busy
       ↓
AWS creates Container 4
       ↓
Container 4 reads V2 ✅
Important conclusion
EventBridge Refresh
       ❌
does NOT mean
       ↓
Destroy old warm containers
       ↓
Force new containers

AWS Lambda manages the lifecycle of warm containers. Simply invoking a Lambda cannot force AWS to terminate all existing warm containers or guarantee that the next request uses a new container.
